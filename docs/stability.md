# 互換性の方針

note-blog-kit は 1.0.0 から [セマンティックバージョニング](https://semver.org/lang/ja/) に従います。この文書は「何を約束するか」と「何を破壊的変更とみなすか」を定めます（#49）。

- **メジャー**（2.0.0 など）：破壊的変更（下の定義）を含む
- **マイナー**（1.1.0 など）：機能の追加。既存のコードはそのまま動く
- **パッチ**（1.0.1 など）：バグ・脆弱性の修正と、note の API の変化への追従

1.0.0 より前（0.x と 1.0.0-rc）は、破壊的変更をマイナーバージョンで入れます。移行のしかたは [MIGRATING.md](../MIGRATING.md) に書きます。

## 公開する範囲

1.0 以降、次のものはメジャーバージョン以外では壊しません。

| 対象 | 範囲 |
| --- | --- |
| subpath | `note-blog-kit`・`note-blog-kit/server`・`note-blog-kit/react`・`note-blog-kit/next` の export と型。公開 API レポート（`etc/*.api.md`）にあるもの（`@internal` を除く） |
| CLI | `note-blog-kit sync` のオプション・終了コード・書き出すファイルの場所と形式 |
| CSS | `note-blog-kit/styles.css` の `nbk-` から始まるクラス名と、CSS 変数（`--nbk-*`） |
| `articles.json` | CLI `sync` が書き出す形式（`version: 1`。型は `NoteSyncedArticleList`） |

次のものは公開する範囲に含めません（パッチ・マイナーで変わることがあります）。

- `@internal` の付いた型・関数、`dist/` の中のファイルの構成（subpath 以外から import しないでください）
- CSS の見た目（既定値）。note の本文の見た目に合わせて変えることがあります。クラス名と CSS 変数の名前は変えません
- エラーメッセージ（`message`）の文面。分岐には `code` を使ってください
- サニタイズの結果の細部。より安全にする変更（許可しない要素を増やすなど）はパッチで行います
- 中継エンドポイントの応答の `Cache-Control` の値

`articles.json` は、項目を足すだけなら `version` を 1 のままにします。項目を変えるか削除するときに `version` を上げ、それはメジャーバージョンで行います。

## 破壊的変更の定義

次の変更は破壊的変更とみなし、メジャーバージョンでだけ行います。

- export（関数・コンポーネント・型）の削除・改名
- 引数・オプション・props を必須にする、受け付ける型を狭める、既定値を変えて結果が変わる
- 戻り値・コールバックに渡す値の型を変える（項目の削除・改名・型を狭める・`null` を許すようにする）
- **出力の型のユニオンを広げる**（利用者の網羅的な `switch` や型の絞り込みが壊れるため）
  - ただし、マイナーバージョンで値が増えると明記しているものは除きます：`NoteErrorCode`・`NoteArticlesHandlerErrorCode`・`NoteEmbed['service']`。これらを `switch` で分けるときは `default` を書いてください
- CSS のクラス名・CSS 変数の削除・改名、要素の入れ子の変更（利用者の CSS のセレクタが当たらなくなる場合）
- `articles.json` の項目の変更・削除
- CLI のオプションの削除・改名、終了コードの意味の変更
- 対応する Node.js・React の下限を上げる

次の変更は破壊的変更とみなしません。

- 型・関数・オプション・項目（出力の型への項目の追加を含む）の追加
- バグ・脆弱性の修正。ドキュメントと違う挙動をドキュメントのとおりに直す場合を含みます
- note の API・RSS の変化への追従（[fix-api-change](../.claude/skills/fix-api-change/SKILL.md) の方針どおり、パッチで出します）
- 上の「公開する範囲に含めないもの」の変更

## 非推奨から削除まで

- 削除・改名する前に、マイナーバージョンで `@deprecated`（TSDoc）を付け、changeset と [MIGRATING.md](../MIGRATING.md) に移行のしかたを書きます
- 非推奨にしたマイナーリリースから**少なくとも 3 か月、かつ 1 つ以上のマイナーリリース**を経てから、次のメジャーバージョンで削除します
- 脆弱性の修正のために、この期間を待たずに挙動を変えることがあります（そのときはリリースノートに理由を書きます）

## サポート範囲

| 対象 | 範囲 | 確かめ方 |
| --- | --- | --- |
| Node.js | 24 以上 | CI（24 の最初の版と最新版） |
| React | 18 / 19（`note-blog-kit/react` を使う場合） | CI（`/react` のテストを React 18 と 19 で実行） |
| Next.js | 15 / 16 の App Router（`note-blog-kit/next` は `next` に依存しない） | examples（Next.js 16） |
| モジュール | ES Modules のみ。CommonJS からは `require()`（require(esm)）で読める | CI（`scripts/check-require.cjs`） |

- Node.js のサポートが終わった版は、次のメジャーバージョンで対応から外します
- note の非公式 API を使っています。note 側の変更で動かなくなった場合は、パッチリリースで追従します（追従できない変更なら、その旨を README と Issue で知らせます）
